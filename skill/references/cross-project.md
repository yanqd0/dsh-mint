# 跨项目登记（cross-project）

> 触发：发现的问题**属于别的项目的能力面**，在本项目改不了，但想登记到对方台账。
> 命令面与门禁见 `commands.md` / `host-dsh.md`；label 命名见 `labels.md`。

## 何时跨项目（可判定）

判据只有一条：**「改哪一个仓库/项目才能修掉它？」**

| 场景 | 归属 | 例（本仓真实案例） |
|---|---|---|
| 缺陷/缺口在**对方的实现或手册**里，本项目只是受害者 | **跨项目** | dsh 手册缺 seat 索引、`webServer` prefix 规则、Inspect 全量查询太贵 |
| 缺陷在**本项目自己的代码/流程**里 | 本项目 | 本插件的门禁写错、skill 口径过时 |
| 本项目**用法**上踩坑，但根因是上游语义 | 先在**本项目**记（并把结论写进 `notes/`）；只有当对方需要改才跨项目 | 上游设计张力（如 approval scope）尚未定案 |

- 反例（**不要**跨项目）：把本仓的 TODO、未完成实现、内部重构登记到别人家。
- 正例：写 `notes/` 时反复「只能读上游源码/产物才知道」——那就是对方的缺口。
- 判不准时**先问用户**；不要两边都提一遍。

## 命令形态（`-p` 必须在子命令之前）

```js
mint({ args: ['-p', 'dsh-dev-dsh', 'list', '--status', 'open'] }); // 读：直接放行
mint({
  args: [
    '-p',
    'dsh-dev-dsh',
    'issue',
    'add',
    '<标题>',
    '--kind',
    'requirement',
    '--priority',
    '1',
    '--label',
    'docs,<来源项目>',
  ],
}); // 写：首次弹确认
mint({
  args: ['-p', 'dsh-dev-dsh', 'plan', 'create', '<标题>', '--milestone', '<对方 running id>'],
});
```

- `--project` 只接受**项目名**（mint 数据目录 `projects/` 下的目录名），不是路径；名字里不能有 `/` `\`。
  候选用 `mint({ args: ["project","list"] })` 查。
- 目标项目不存在 → 工具直接拒绝并给候选（**不会**静默新建项目库，也不会落到本项目）。
- `MINT_DB_PATH` 单文件模式下不支持跨项目。
- 跨项目**读**会顺带把当前目录写进对方的 `abs_dir` 列表（mint 语义），故不要用 `-p` 做无意义探测。

## 来源标注（#81 口径）

在**对方**项目登记时，必须留下来源，否则对方无法回溯是谁提的：

1. **label 追加来源项目名**：小写、等于 mint 项目名（如 `dsh-mint`），与内容 label 并列
   （例：`docs,dogfood,dsh-mint`）。label 自动注册；来源 label 不替代内容 label，也不占「≤5 个」之外的额外含义。
2. **标题/body 首节写来源**：`## 来源` 下首行写 `来源：<来源项目> <plan/issue 指针> + 一句话场景`。
   指针给**本仓**的 plan/issue 编号或 `notes/` 文件，便于对方回查。
3. **不重复提**：对方已有 issue 覆盖的内容，只补「我们的实测证据/差异」，不另起一条（先搜：
   `mint({ args: ["-p","<对方>","search","<关键词>"] })`）。

## 反查方向（两边都不认账的解药）

`mint` 的 link 是**库内**语义（issue id 跨项目会撞），跨项目只能用文本 cross-ref：

- **对方侧**（被登记的项目）：`## 来源` 首节 → 指回来源项目。
- **来源侧**（本项目）：在**本次工作**的 plan/issue body 里记一行「已向 `<对方项目>` #N 登记」，
  必要时把对方的验收条件抄一句。用 `issue set <id> --body-append`（见 `body-editing.md`）。
- 登记完**不要**把对方 issue 挂进本项目的 plan/milestone（跨库 id 无意义）。

## 门禁与通道

- **写操作**：同一会话 + 同一目标项目，首次弹一次确认（文案含目标项目与动作），之后免问；
  换目标项目或换会话会再问。这是宿主 `tools/pre-execute` 的门禁，**不是**沙箱提权。
- **子代理**：approval 被 pin `never` ⇒ `ask` 退化为拒绝。跨项目**读**可用，**写**不可用
  （子代理只做调研，登记交回主 agent）。
- **bash 兜底**：只在工具不可用/插件未安装时才用。插件在场时，可识别的裸
  `mint -p <项目> <写命令>`（含 `MINT_PROJECT=` 前缀）走同一道确认；引号、重定向、`$( )`、
  脚本文件等形态不识别，那时只有沙箱提权审批兜底。
- **不做**：`--db`（单文件模式）、跨项目聚合视图。两者都不在本 skill 的支持面内。
